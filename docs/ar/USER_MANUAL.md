# Jervis AI Hub: دليل الاستخدام

[English](../USER_MANUAL.md)

Jervis AI Hub هو mod لـ Claude Code. بيوصّل اشتراكات الذكاء الاصطناعي ومفاتيح الـ API اللي عندك أصلًا، ويخلي Claude يسألهم، ويقارن إجاباتهم، ويشغّل عليهم شغل في الخلفية، أو يسلّمهم مهمة برمجة. والقرار في إيدك: مفيش حاجة بتقرا مشروعك أو بتغيّر ملف من غير ما توافق.

الدليل ده لإصدار `0.11.0`.

## المطلوب

- Claude Code (الـ terminal أو تطبيق الديسكتوب أو إضافة الـ IDE)، على Windows أو macOS أو Linux.
- على Linux: `secret-tool` (libsecret)، و `zenity` أو `kdialog` عشان تكتب مفاتيح الـ API.
- الـ CLI الرسمي لكل اشتراك هتوصّله، متثبّت ومسجّل دخول فيه:

| عشان توصّل | ثبّت | الإصدار |
| --- | --- | --- |
| ChatGPT (اشتراكك في ChatGPT، عن طريق Codex) | Codex CLI (`codex`) | أي إصدار |
| Antigravity | Antigravity CLI (`agy`) | `1.5` أو أي `1.x` أحدث |
| OpenCode Zen (المجاني) وكل providers مفاتيح الـ API | OpenCode (`opencode`) | `2.x` |

- Node.js، بس لو هتعمل delegation لـ Antigravity عن طريق Jervis Relay.

## التثبيت والتحديث والإزالة

الـ repository خاص (private). عشان تثبّت لازم يكون عندك صلاحية قراءة عليه في GitHub، وgit credential لـ github.com على جهازك (SSH key، أو `gh auth login` وبعدها `gh auth setup-git`).

**التثبيت** من الـ prompt في جلسة terminal:

</div>

```
/plugin install ai-subscriptions --marketplace keroloszakaria/jervis-ai-hub
```

<div dir="rtl">

جاوب بـ `y` عشان الـ marketplace يتضاف، وبعدين اختار الـ user scope. أو من الـ shell:

</div>

```bash
claude plugin install ai-subscriptions --marketplace keroloszakaria/jervis-ai-hub
```

<div dir="rtl">

في تطبيق الديسكتوب: دوس **+** جنب خانة الـ prompt ← **Plugins** ← **Add marketplace** واكتب `keroloszakaria/jervis-ai-hub` ← **Add plugin**.

**التحديث:**

</div>

```bash
claude plugin update ai-subscriptions
```

<div dir="rtl">

**الإزالة:**

</div>

```bash
claude plugin uninstall ai-subscriptions
```

<div dir="rtl">

إزالة الـ plugin مش بتخرّجك من أي CLI. لو عايز تمسح مفتاح API محفوظ، افتح الـ provider ده ودوس **فصل** (Disconnect) قبل الإزالة.

## فتح اللوحة

اللوحة بتفتح لوحدها أول ما الجلسة تبدأ. عشان تفتحها تاني اكتب:

</div>

```
/ai-providers
```

<div dir="rtl">

فوق هتلاقي العنوان، وعدد الـ providers الجاهزين (مثلًا `● 2/3 جاهز`)، وزرار **+ إضافة**، وأربع تبويبات: **نظرة عامة** و**الموديلات** و**النشاط** و**الإعدادات**.

أول مرة، الـ hub بيحاول يوصّل ChatGPT وAntigravity وOpenCode، ويربط اللي إنت مسجّل دخول فيه منهم. مش بيتبعت أي prompt. ولو Codex متثبّت بس إنت مش مسجّل دخول فيه، ممكن يفتحلك لينك تسجيل الدخول في ChatGPT.

## توصيل provider

دوس **+ إضافة**. الـ providers متقسّمين تلات مجموعات، وتقدر تدوّر عليهم بالاسم:

- **تسجيل دخول باشتراك:** ChatGPT (Codex) وAntigravity.
- **محلي أو مجاني:** OpenCode Zen (المجاني)، من غير مفتاح.
- **مفتاح API:** DeepSeek وOpenRouter وGoogle Gemini API وxAI Grok وMistral وGroq وMoonshot Kimi وAlibaba Qwen وZhipu GLM وCerebras وFireworks وPerplexity وMiniMax وAnthropic API وOpenAI API وZ.AI وTogether AI وDeep Infra وNVIDIA NIM وHugging Face وCohere وغيرهم (37 في المجموع). كلهم بيشتغلوا عن طريق OpenCode.

دوس **اتصال** على أي صف:

- **ChatGPT:** الـ hub بيشغّل `codex login` ويوريك لينك، وتكمّل تسجيل الدخول في المتصفح.
- **Antigravity:** الـ hub مايقدرش يسجّلك. شغّل `agy` مرة في terminal وسجّل دخول، وبعدين دوس **اتصال** تاني.
- **مفتاح API:** بتفتح نافذة نظام مخفية الكتابة اسمها "Jervis AI Hub - &lt;provider&gt;". الصق المفتاح ودوس **Save**. ولينك **هات مفتاح ↗** بيفتحلك صفحة المفاتيح بتاعة الـ provider.

### معنى الحالة

| الحالة | المعنى |
| --- | --- |
| ● متأكد منه | طلب اختبار نجح. |
| ◐ ما اتجربش | مسجّل دخول، بس لسه ماحدش جرّب طلب. |
| ● الاختبار فشل | آخر اختبار ماشتغلش. |
| ○ مش مسجّل دخول | تسجيل الدخول أو المفتاح مش موجود. |
| ○ الـ CLI مش موجود | الـ CLI بتاع الـ provider مش متثبّت. |
| ◌ بيتفحص… | الـ hub بيشيّك على تسجيل الدخول. |
| ○ مقفول | إنت اللي قفلت الـ provider. |

إنك تكون مسجّل دخول مش معناه إن الطلبات شغّالة. افتح الـ provider ودوس **اختبار الاتصال**. الاختبار بيبعت prompt حقيقي قصير، وبيتحسب من اشتراكك أو رصيد الـ API.

## اللوحة تبويب تبويب

### نظرة عامة

- المربعات: **جاهز** و**الطلبات** ومتوسط زمن الرد.
- **الـ Providers:** كل provider متوصّل بحالته وموديله والـ effort. **فتح ›** بيفتح صفحته.
- **الحدود:** حدود جلسة Claude دي، والحدود اللي كل provider متوصّل بيقول عليها. **تحديث** بيقراها تاني.
- **الأحدث:** آخر تلات طلبات، و **كل النشاط ›** بيفتح تبويب النشاط.

### صفحة الـ provider

- عدد الطلبات ومتوسط زمن الرد والـ tokens (داخل / خارج؛ وproviders الـ OpenCode، اللي الـ CLI بتاعهم مش بيقول الاستهلاك، بيظهر عندهم "not reported").
- كارت **الحدود:** الخطة، ومؤشر لكل فترة ("N% used · resets in …")، والمصدر اللي القراية جاية منه.
- **الموديل:** اختار الموديل، وبعدين الـ **Effort** (بس الـ efforts اللي الموديل ده بيعرضها). لو مااخترتش effort، بيتستخدم الافتراضي بتاع الـ CLI.
- **الاتصال:** تسجيل الدخول، وآخر اختبار، وهل الـ delegation متاحة، وطريقة الحساب.
- **اختبار الاتصال** و **تحديث الموديلات**.
- **آخر الأخطاء:** آخر تلاتة.
- **إدارة:** **إيقاف** / **تشغيل**، و **فصل**. الفصل بيشيل الـ provider من الـ hub ومعاه مفتاح الـ API المحفوظ، ومش بيخرّجك من الـ CLI أبدًا.

### الموديلات

- دوّر في موديلات كل الـ providers المتوصّلين. فلتر بالـ **Provider**، والـ **Capability** (صور، تفكير، استدعاء tools، بحث في الويب، context ≥ 200k)، والـ **Level** (خفيف، متوسط، تقيل).
- **☆** بتعلّم على الموديل إنه مفضّل، و **★ المفضّلة** بتعرض المفضّل بس. الموديلات المفضّلة بتظهر كمان في قواعد التوجيه.
- **التفاصيل ›** بتعرض اللي المصدر بتاع الموديل بيقوله: الـ ID، والـ effort، والـ context، والمدخلات، والـ tools، والسعر الرسمي لكل مليون token، والمستوى. السعر الرسمي ده مش اللي اشتراكك بيكلّفه.
- من التفاصيل تقدر:
  - تحدد المستوى بنفسك (**حدد المستوى**)؛
  - تخلي الموديل هو الافتراضي لمهمة (**افتراضي لـ**)، ودي بتعمل قاعدة توجيه؛
  - تخليه موديل الـ provider ده (**Use for &lt;provider&gt;**).

الـ hub بيعرض اللي كل مصدر بيقوله بس، ومفيش حاجة متخمّنة.

### النشاط

- المربعات: **الطلبات**، واللي فشل، ومتوسط زمن الرد، و **تكلفة الـ API** لو OpenCode سجّل تكلفة.
- رسم لزمن الرد لآخر 30 طلب (في تطبيق الديسكتوب)، وجدول **حسب الـ Provider**.
- قايمة الطلبات (آخر 40)، وتقدر تفلترها: All وAsk وCompare وTest وDelegate.
  - كل صف عليه ✓ نجح، أو ✗ خطأ، أو ● شغّال، أو – اتلغى.
  - **›** بيفتح التفاصيل: الوضع، والموديل، وحجم الـ prompt، والتقدّم، والاستهلاك، والملفات اللي اتغيّرت.
  - الطلب الشغّال بيوريك بقاله قد إيه وكتب قد إيه، و **إيقاف** بيقفله.
- **تصدير** بيكتب القايمة كـ `.json` و `.md` في `<فولدر temp>/jervis-ai-hub/exports/`. فيها بيانات وصفية بس: مفيش prompts ولا إجابات ولا نص الأخطاء.
- **مسح** بيفضّي القايمة.

## الاستخدام من Claude

اطلب من Claude بكلام عادي. مثلًا:

- "اسأل Antigravity عن رأيه في الخطة دي."
- "قارن موديلين تانيين على السؤال ده."
- "قسّم المراجعة دي لأجزاء وشغّلها في الخلفية."

Claude بيستخدم الـ tools دي:

| الـ tool | بيعمل إيه |
| --- | --- |
| `ask_ai` | إجابة واحدة من provider واحد. قراية بس، إلا لو اتطلب غير كده. |
| `compare_ai` | نفس الـ prompt لـ 2 لـ 5 providers جنب بعض. دايمًا قراية بس. |
| `start_job` / `job_status` | شغل في الخلفية، وبعدين نتيجته. |
| `delegate_ai` | مهمة برمجة تتسلّم لـ Codex أو Antigravity، في نسخة من الفولدر بتاعك. |
| `apply_changes` | يسألك تاني على تغييرات كنت سايبها لبعدين. |

الـ AI التاني مش بيشوف المحادثة بتاعتك، بيشوف الـ prompt اللي Claude كتبه بس. طلب القراية بيشتغل في فولدر فاضي، فالـ provider مش بيشوف غير الـ prompt ده. ومش بيشوف ملفات مشروعك غير لو Claude بعت الفولدر وإنت وافقت.

### مستويات الشغل

كل طلب ممكن يتبعت معاه مستوى، عشان الشغل البسيط مايصرفش موديل قوي:

- **خفيف:** بحث، ومعلومة سريعة، وتلخيص، وإعادة تسمية، وكود متكرر.
- **متوسط:** تعديلات الكود اليومية والشرح.
- **تقيل:** الـ bugs الصعبة، والـ architecture، والأمان، والمراجعات الدقيقة.

الـ hub بيختار موديل وeffort يناسبوا المستوى. ولو "اختار أنسب موديل لكل مهمة" شغّال (وده الافتراضي)، الشغل التقيل عمره ما بيتنزّل لموديل أضعف: لو مفيش موديل يقدر عليه، الطلب بيترفض. ولو مقفول، المستوى مش بيحدد الموديل.

## السؤال المباشر: /ask-ai

</div>

```
/ask-ai [provider] [task] [level] [--preview] your question
```

<div dir="rtl">

- **provider:** الـ id أو أول كلمة من اسم provider متوصّل، زي `chatgpt` أو `antigravity` أو `deepseek`.
- **task:** `general` أو `code` أو `review` أو `reasoning` أو `fast` أو `vision`.
- **level:** `light` أو `standard` أو `heavy`.
- **--preview:** بيوريك الـ provider والموديل والسبب والصلاحيات والمهلة وحجم الـ prompt، ومش بيبعت حاجة.

أول تلات كلمات ممكن ييجوا بأي ترتيب، وأول كلمة مش واحدة منهم بيبدأ عندها السؤال. لو مفيش provider ولا task، الـ hub بيختار أحسن موديل متوصّل.

</div>

```
/ask-ai deepseek code Why does this regex match the empty string? ^(a|b)*$
```

```
/ask-ai --preview heavy Review this migration plan for data loss.
```

<div dir="rtl">

`/ask-ai` دايمًا قراية بس، ومش بيبعت غير السؤال. الإجابة بتبدأ بـ `[provider · model · effort · time]`، ولو الـ CLI بيقول، بيظهر عدد الـ tokens والتكلفة اللي OpenCode سجّلها.

## الـ hub بيختار provider إزاي

لكل طلب، بالترتيب ده:

1. الـ provider اللي متسمّي في الطلب.
2. **قاعدة التوجيه** بتاعتك للمهمة.
3. الـ provider الافتراضي (**غير كده**)، بأحسن موديل عنده للمهمة.
4. **الاختيار الذكي**، لو "اختار أنسب موديل لكل مهمة" شغّال.
5. لو الاختيار الذكي مقفول: أول provider جاهز.

الاختيار الذكي بيدّي درجة لكل موديل متوصّل على حسب اللي مصدره بيقوله (التفكير، واستدعاء الـ tools، والـ context، والصور، والسعر)، وعلى حسب الحدود اللي كل provider بيقول عليها.

الـ provider اللي قرايته بتقول إنه وصل للحد بيتعدّى. ونفس الكلام للقاعدة اللي موديلها مابقاش موجود أو ناقصه حاجة المهمة محتاجاها (مهمة الصور محتاجة موديل بيقبل صور). والإجابة بتقول السبب.

**البديل (fallback)** مقفول افتراضيًا. لو شغّلته، طلب القراية اللي فشل بسبب حد، أو مشكلة شبكة، أو provider مش متاح، ممكن يروح لـ provider تاني (من 1 لـ 3 بالكتير). الـ hub بيسألك الأول، لأن الـ prompt ساعتها هيروح لحد إنت مااخترتوش. الكتابة والـ delegation عمرهم ما بيروحوا لبديل ولا بيتعادوا.

## الكتابة والـ delegation

الكتابة (`ask_ai` في وضع الكتابة) أو الـ delegation (`delegate_ai`) ممكن يغيّروا ملفات. وبيمشوا كده:

1. **بتتسأل الأول:** "Let &lt;provider&gt; change files in a copy of &lt;folder&gt;? You see the changes before any reach the folder. Nothing is committed." وتختار **Allow** أو **Deny**.
2. **الشغل بيحصل في نسخة.** الـ hub بينسخ الفولدر بتاعك في `~/.claude/jervis-ai-hub/work/<run>/`، ومش بينسخ:
   - فولدر `.git`، والملفات اللي `.gitignore` بيتجاهلها؛
   - الـ links والـ submodules؛
   - ملفات الأسرار: `.env` و `.env.*` و `*.pem` و `*.key` و `*.p12` و `*.pfx` و `id_rsa*` و `id_ed25519*` و `.npmrc` و `.netrc` وزيّهم؛
   - الملفات اللي جواها حاجة شكلها مفتاح؛
   - أي حاجة كاتبها في `.jervisignore` في أول الفولدر، بنفس طريقة كتابة `.gitignore`؛
   - الفولدرات اللي بتودّي برّه المشروع.

   الفولدر اللي فيه أكتر من 20,000 ملف أو 300 MB مش بيتنسخ، ومش بيتبعت حاجة.
3. **بتراجع.** لوحة **مراجعة التغييرات** بتوريك الـ diff بتاع كل ملف، وإنت بتجاوب في السؤال:
   - **Apply** بيكتب التغييرات في الفولدر بتاعك، من غير stage ولا commit.
   - **Keep for later** بيحتفظ بيها 7 أيام. بعدين اطلب من Claude يطبّق الـ run `run-…`، وهو هيستخدم `apply_changes`.
   - **Discard** بيرميها.

الـ Apply مش بيلمس غير الملفات اللي ماتغيّرتش في الفولدر بتاعك من ساعة ما النسخة اتعملت. لو أي واحد منهم اتغيّر، مفيش حاجة بتتطبّق. ولو قفلت السؤال من غير ما تجاوب، بيتحسب **Keep for later**.

**مين يقدر يعمل إيه:**

| الـ provider | الكتابة | الـ delegation |
| --- | --- | --- |
| ChatGPT (Codex) | أيوه، محصورة في الفولدر | أيوه، والـ hub هو اللي بيشغّلها |
| OpenCode وproviders مفاتيح الـ API | أيوه، محصورة في الفولدر | لأ |
| Antigravity | بس لو "اسمح بكتابة مش محصورة في المجلد (Antigravity)" شغّال | نفس الشرط، عن طريق Jervis Relay (محتاج Node.js والـ skill اسمها `agy-delegate`) |

الكتابة بتاعة Antigravity مقفولة افتراضيًا، لأنها مش محصورة في الفولدر: ممكن تغيّر أي ملف إنت تقدر تغيّره.

**المهلة:** الاختبار بيقف بعد دقيقتين، والقراية بعد 5، والكتابة أو الـ delegation لـ Codex بعد 10، والـ delegation لـ Antigravity عن طريق Jervis Relay بعد 30. والطلب اللي الـ hub مايقدرش يتأكد إنه خلص بيتقال عليه إنه ممكن يكون لسه شغّال.

## المهام في الخلفية

لو المهمة كبيرة، Claude ممكن يقسّمها أجزاء ويبدأ كل جزء بـ `start_job` بالمستوى بتاعه. الجزء بيشتغل على AI تاني (قراية بس) أو على subagent من Claude.

- بالكتير 4 مهام بيشتغلوا في نفس الوقت.
- فيه شريط فوق الـ prompt بيعرض آخر 5 مهام: ◐ شغّالة، ✓ خلصت، ✕ فشلت، ■ اتوقفت. وبيوريك مستواها، وبتشتغل فين، وبقالها قد إيه.
- **إيقاف** بيقفل المهمة الشغّالة على AI تاني. مهمة الـ subagent ماينفعش تتوقف من الـ hub.
- **Clear ended** بيخبّي المهام اللي خلصت، ونتايجها بتفضل موجودة تقدر تقراها.
- لما مهمة تخلص بيجيلك إشعار، ونتيجتها (لحد 4000 حرف) بتتضاف للمحادثة إلا لو قفلت ده. و `job_status` بيقرا النتيجة كلها.
- المهام تبع الجلسة بتاعتها: لما الجلسة تخلص، مهامها بتخلص معاها.

## الحدود والتكلفة

- **Claude:** حدود الجلسة دي نفسها (الـ 5 ساعات، والأسبوعي…)، وبتتحدّث بعد كل رد.
- **ChatGPT:** فترات الخطة اللي Codex بيقول عليها.
- **Antigravity:** اللي `agy /usage` بيقوله.
- **DeepSeek وOpenRouter وMoonshot Kimi وSiliconFlow:** رصيد المفتاح أو المصروف. باقي الـ providers مالهمش endpoint منشور للرصيد، والـ hub بيقول كده.

الـ hub عمره ما بيخمّن أو بيألّف رقم:

- القراية اللي عدّى عليها أكتر من 30 دقيقة بتتعلّم إنها قديمة ومش بتأثّر في التوجيه. دوس **تحديث**.
- بيجيلك إشعار عند 80% و95% من الفترة، ولما provider يقول إنه وقف.
- **التكلفة** بتظهر بس لما OpenCode يسجّلها لطلب (providers مفاتيح الـ API). الاشتراك مالوش فاتورة على كل طلب.

**التشخيص:** **شغّل الفحوصات** بيشيّك على كل CLI وإصداره، وحصر القراءة في Codex، وتخزين المفاتيح الآمن، وNode.js بتاع Jervis Relay، والـ delegation لـ ChatGPT وAntigravity وOpenCode Zen، وبيانات models.dev.

## الخصوصية والأمان

- **مفاتيح الـ API** بتتكتب في نافذة نظام مخفية الكتابة، عمرها ما بتتكتب في الشات. وبتتحفظ في التخزين الآمن بتاع النظام: Windows DPAPI، أو الـ Keychain في macOS، أو الـ Secret Service في Linux. عمرها ما بتظهر، ولا بتتسجّل في log، ولا بتتكتب كنص عادي، ولا بتتحط في command line. المفتاح بيوصل للـ CLI كـ environment variable للطلب ده بس.
- **تسجيلات الدخول** هي الـ CLIs الرسمية بتاعة الـ providers. الـ hub عمره ما بيقرا cookies المتصفح أو الـ session tokens.
- **الـ prompts والإجابات** بتفضل خاصة: النشاط بيحتفظ بالأحجام والنتايج بس، إلا لو شغّلت المعاينات المتخبّي منها الأسرار.
- **مشروعك** مش بيتقري غير بموافقتك، ومش بيتغيّر غير بعد **Allow** وبعدها **Apply**.
- **الـ git بتاعك** محمي: الـ hub مش بيشغّل أي hook أو filter من الـ repository بتاعك، وبيرفض أي run غيّر الـ branches أو الـ refs.
- **مفيش لفّ في دواير:** الـ hub اللي شغّال جوه agent بدأه hub تاني مش بيبعت حاجة لقدّام.

الـ hub بيحتفظ على الجهاز بالحاجات دي:

| فين | إيه |
| --- | --- |
| الـ plugin store بتاع Claude Code | التوصيلات، والإعدادات، والمفضّلة، وقوايم الموديلات، والنشاط (من غير prompts). وعلى Windows، المفاتيح متشفّرة. |
| `~/.claude/jervis-ai-hub/work/` | النسخ اللي اتعملت للكتابة، والـ runs اللي محتفظ بيها لبعدين (بتتمسح بعد 7 أيام). |
| `~/.claude/jervis-ai-hub/relay/` | نتايج الـ delegations اللي عن طريق Jervis Relay. |
| `<temp>/jervis-ai-hub/` | الفولدر الفاضي لطلبات القراية، والملفات اللي صدّرتها. |

## Codex وAntigravity كـ host

نفس الـ hub ممكن يشتغل كمان جوه Codex وجوه Antigravity، كـ plugin تبعهم. هناك يقدر يسأل ويقارن ويشغّل مهام ويوريك الموديلات والحدود. بس مايقدرش يكتب ولا يعمل delegation ولا يقرا مشروعك، لأن الـ hosts دول مش بيدّوله طريقة يسألك بيها الأول. وجوه كل host، الـ AI بتاع الـ host نفسه عمره ما بيتبعتله طلبات.

التثبيت والتفاصيل: [docs/integrations/CODEX.md](../integrations/CODEX.md) و [docs/integrations/ANTIGRAVITY.md](../integrations/ANTIGRAVITY.md) (بالإنجليزي).
